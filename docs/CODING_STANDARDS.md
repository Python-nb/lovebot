# 开发与界面规范

本工程是原生微信小程序，不使用浏览器 DOM API，不需要构建 npm 运行包。浏览器预览只是开发适配器，不作为硬件验收证据。

## 统一设计语言

- 设计源：`miniprogram/app.wxss`。沿用海军蓝/橙色品牌，同时维护浅色与深色，不为单页另起配色。
- 所有筛选/选项共用 `capsule-group → capsule-button → capsule-face`。外层原生 button 负责点击，内层 text 负责视觉。
- 胶囊可见高度 30px、点击区域 44px、相邻间距 8px、字号 12px、圆角 999px；同组等宽、横纵居中。对应 `--capsule-*` 变量集中维护，禁止每个入口重新覆盖。
- 应用范围：排行指标、排行时间、统计时间、图表指标、外观选择。选中统一橙色，提供 `aria-pressed`，不能只靠颜色表达状态。
- 设备连接入口复用同一扁胶囊外观；首页与“我的发球机”复用 device-card 模板。设备名称、红色未连接 / 绿色呼吸灯已连接及真实 RSSI 同步展示，不提供模拟信号。
- 训练启停、表单和导航保留各自操作层级及至少 44px 点击区域；训练启停至少 48px，不缩成筛选胶囊。帮助问号可见 24px / 字号 13px，触摸 44px。
- “我的”页头像使用原生 button 作为账号入口，提供可读的登录/账号管理提示与动态无障碍标签；昵称编辑是相邻独立按钮，不把头像点击解释为读取微信头像或授权手机号。
- 普通失败用原生 3 秒 Toast，非顶部常驻横条；切页、隐藏、卸载收起。现场停机等安全信息仍显示在训练状态区。
- 首页中性表面与橙色重点，避免多套渐变按钮；装饰篮球使用本地原创插画，不用圆圈斜线等 CSS 占位图形。
- 新增界面必须同时检查两种主题、320/390/430px、长文案、安全区和固定导航遮挡。自动化结构测试不能代替真实尺寸与视觉检查。

## 代码职责

- `lib/protocol.js`：命令编码、回传解析、拆包粘包及字段校验；不引用 wx、不操作页面。
- `lib/ble.js`：微信蓝牙 API、服务/特征校验、连接生命周期；不生成成绩，不重发控制命令。
- `lib/records.js`：本机记录校验、持久化及统计。仅接受 BLE 来源；模式校验使用自有属性，不能把 Object 原型键当合法模式。
- `lib/theme.js`：主题偏好、系统回退与原生颜色映射。
- `lib/privacy.js`：微信隐私授权/正式指引的回调适配，以及与实际数据流一致的本机数据说明。平台未同意不访问 BLE，缺少 API 不默认放行。
- 页面控制器：交互/状态编排。修改控制流程必须附状态时序测试；不要把协议、存储、统计继续内联进页面。
- WXML：仅展示和事件绑定。动态样式绑定完整的 `barStyle` 字符串，不混写 CSS 值与模板插值。
- 开发脚本、测试、预览、依赖全部放在 `miniprogramRoot` 以外。生产 JS 禁止 eval/new Function、浏览器和 Node 专属全局变量。

## 自动检查

使用 package.json 声明的 Node 版本（本次验证 v24.12.0），依赖由 package-lock.json 锁定。

```sh
npm ci
npm ci --prefix server
npm run quality
```

`quality` 依次执行：

1. `check`：JS/JSON 语法、页面注册完整性。
2. `lint`：ESLint 推荐正确性规则、严格相等、未定义/未使用变量，0 警告门槛；原生代码和开发脚本使用不同全局变量。
3. `format:check`：Prettier 的 JS/JSON/WXSS/WXML 格式约束。修正格式使用 `npm run format`，生成的 preview 不手改。
4. `assets:check`：按 project.config.json 的忽略规则检查运行资源；单个图片/音频不超过 200000 B，原始源文件总量不超过本项目 1.5 MB 预算，校验静态图片及动态导航的缺失/无引用资源。此大小不是微信最终编译包大小。
5. `test`：协议、BLE 桩、状态控制、存储、主题和隔离 DOM 回归；测试不启动浏览器/服务器，不发送真实蓝牙指令。
6. `test:server`：Express 接口、微信上游桩、鉴权/隔离/改密/删除回归。接口测试会临时监听本机随机端口并自动关闭，存储替身不等于真实 MySQL。

随后在微信开发者工具查看编译、问题面板、质量扫描与运行日志。不得通过关闭合法域名检查、屏蔽日志、排除必须资源或伪造状态来通过检查。

格式器使用严格 HTML 空白规则处理 WXML；改动后仍需原生 wcc/wcsc 编译与模板行为回归。关键布局测试不应依赖文件是否压成一行。

## 生产边界

- 控制写入不自动重试。超时不等于硬件没有执行；停止也必须现场核对。
- 扫描异常清理定时器/发现流程；卸载同步移除监听，忽略迟到回调，再清理原生连接资源。
- 存储失败不显示成功；恢复草稿不恢复发球；真实设备计数语义由厂商/实机确认。
- 不把本机昵称、wx.login 的临时 code 当真实登录；AppSecret、上游 session_key 和数据库凭据不进入客户端。客户端仅持有服务端核验后签发的不透明业务会话，保存在微信 storage，不进入页面 data、日志或仓库。
- 没有提交审核/发布授权时不上传。静态检查、质量扫描和模拟器通过都不等于完成真实设备或生产验收。

微信官方依据、后台待确认事项见 [微信隐私与发布规则](WECHAT_COMPLIANCE.md)。用户会话中确定的长期规则见项目根 AGENTS.md；以后先阅读，避免只改一个入口或重复退回占位图形。

用户已指定 lovebot Git 仓库，原模板保留在初始提交。只纳入明确审核的源文件、锁文件及规则；不提交 node_modules、个人 IDE 配置或凭据，不自动推送触发云端构建。
