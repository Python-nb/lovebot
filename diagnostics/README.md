# 开发版 BLE 诊断服务（独立部署）

此服务只接收匿名、限量的 BLE 诊断批次并写入自身的结构化应用日志；没有 MySQL、微信 AppSecret、账号 Token 或训练记录接口。2026-10-27 用户选择复用 `prod-d5g0ea4ci0a964b1a` 云环境；**必须在该环境新建独立诊断服务，不得覆盖现有 `express-7wuk` 账号服务，也不得继承其 MySQL、AppSecret 或账号密钥配置。**同环境部署不等于正式版可调用，客户端仍仅在 `develop` 版本允许测试者开启。

部署前在现有 `prod` 环境创建独立诊断服务，禁用公网访问并核对平台对容器调用的访问限制，设置该服务应用日志的自动删除期限（建议不超过 7 天），核对正式隐私指引；云平台日志保留期限不是代码可代替设置的。以 `diagnostics/` 为 Docker 构建上下文（手动上传代码包时 Dockerfile 位于包根目录；仓库部署时目标目录为 `diagnostics`），服务监听 8080，探针 `/healthz`。确认独立服务、入口限制及日志保留后才在诊断服务设置 `DIAGNOSTICS_INGEST_ENABLED=true`；随后把环境 ID 和新服务名填写到 `miniprogram/config/diagnostics.js` 并将 `enabled` 设为 `true`。配置只包含公开路由，不要放凭据。任何一项未核验都保持关闭。客户端的开发版判断不是服务端鉴权，不能用它代替平台访问限制。

测试者在开发版首页手动开启，每次生成新的 24 位诊断编号，最多 5 分钟，切后台/关闭时停止，不写本机缓存。批次最多 8 个事件，服务端按来源地址、编号和全局频率限流。日志只存白名单事件、时间、错误码、报文长度及最多 3 条仅保留数字位数/分隔符的 24 字节形状样本。根据诊断编号在该服务的应用日志中查询：

| 事件 | 判读 |
| --- | --- |
| `notify_ok` / `notify_error` | 通知订阅结果，不能代替实际收到数据 |
| `notify_raw` / `frame_valid` | 蓝牙回调到达／报文解析为有效帧，缺后者需核对脱敏形状与厂商协议 |
| `start_requested` → `gate_blocked` | 安全检查拦截，`code=1` 未连接、`2` 无 3.5 秒内有效帧、`3` 自由模式不符；没有发送启动指令 |
| `gate_ok`（两次）→ `write_ok phase=start` | 启动写入 API 返回成功，不等于机器真正开始工作 |
| `write_error` / `receive_timeout` | 写入结果不确定／超过 3.5 秒无有效回传并尝试停止，必须现场确认设备 |

不对诊断上传重试设备指令。旧开发版无诊断记录，须由测试者在新开发版重新开启并复现。当前仓库配置默认关闭；本地测试不等于真实设备或云平台日志验收。
